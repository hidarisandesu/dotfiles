# dotfiles リポジトリの運用ルール

セットアップと運用の手順は .claude/WORKFLOW.md を参照する。

## 公開リポジトリである
誰でも内容と履歴を読める。トークン・鍵・パスワードなど、公開できないものを絶対にコミットしない。一度プッシュした内容は履歴から消せない前提で扱う。

## apply は配置だけを行う
`chezmoi apply` が行うのは、設定ファイルの配置と、Windows の初回だけ実行されるスクリプトによる Git for Windows の導入である。ツールの導入・更新・削除は、台帳(home/.chezmoidata/tools.yaml)に載せて setup-tools(apply が ~/.local/bin/setup-tools に配置する選択式導入コマンド)に任せる。apply にツールの導入処理や、実行時にユーザーへ知らせる出力を足さない。

## settings.json はマージ配布である
~/.claude/settings.json は modify テンプレート(home/dot_claude/modify_settings.json)で配布する。テンプレートに書かれた配布キーだけを、ローカルに clone したリポジトリの内容(以下、正本)の値で上書きし、それ以外のキー(model・hooks・enabledPlugins・permissions 等)は実機の値を保持する。マシン固有の設定はこの「非配布キー」として実機に残し、正本へ取り込まない。

## このリポジトリはベースである
正本は全マシン共通のベースである。マージ配布によりマシン固有の設定は apply で消えないため、`chezmoi status` / `chezmoi diff` の出力は空になるはずであり、差分が出たらそれは解消すべき乖離である。
- 共通設定を変えるときは正本(home/ 配下)を編集する。ホーム側だけを編集すると他マシンに伝わらないうえ、配布対象の値は次の apply で正本の値に戻る
- リモートの変更は `chezmoi update` で取り込んでよい(マージ配布によりマシン固有の設定は上書きされないため、稼働中のマシンで実行してよい)
- マシン固有の設定を、共有する意図なく正本に取り込まない

## リモートとの同期は sync-dotfiles スキルを必ず使う
sync-dotfiles スキルは、ローカルのみに変更があれば push、リモートのみにあれば pull、双方に差分があれば rebase を実行し、正本・リモート・ホームの一貫性を保つ。手動で個別に実行すると手順漏れで乖離が起きる。

## パスは相対パスで指定する
Claude Code の権限設定はプロジェクトルートからの相対パスで照合されるため、ツールに渡すファイルパスは相対パスで指定する。
